StandAlone Agent — Robinhood Chain HTTP 403 Fix Patch

WHY THIS PATCH EXISTS
- Current Blockscout data API requires a Blockscout PRO API key, including the free tier.
- The previous live test queried the public explorer's /api/v2 routes without a key, causing 403 responses.
- The previous test output did not display nested error details cleanly; this version does, while redacting secrets.
- Alchemy HTTP 403 still needs to be checked in your own Alchemy dashboard; this patch cannot repair a disabled/wrong API key.

SAFE APPLY
1. Stop pnpm dev with Ctrl+C.
2. Extract this ZIP into the StandAlone-Agent project root and replace the matching files.
3. Do NOT replace .env.local with .env.example.
4. In .env.local, keep your existing variables and add these two lines using your own fresh keys:
   ALCHEMY_ROBINHOOD_API_KEY=YOUR_ROBINHOOD_MAINNET_ALCHEMY_KEY
   BLOCKSCOUT_PRO_API_KEY=proapi_YOUR_FREE_BLOCKSCOUT_KEY
5. Create/verify Alchemy app: https://dashboard.alchemy.com/
   - App/network must be Robinhood Chain Mainnet.
   - Copy the HTTP endpoint from its Endpoints tab; the official pattern is
     https://robinhood-mainnet.g.alchemy.com/v2/{API_KEY}
   - Do not use a key from a different app/network, a deleted/rotated key, or a full endpoint URL in the variable; variable expects only the key.
6. Create a free Blockscout PRO API key at https://dev.blockscout.com.
   - The key typically starts with proapi_. Keep it server-side and do not paste it in chat.
7. Restart server: pnpm dev
8. In a second CMD window, from the project root run:
   node scripts/test-robinhood-live.mjs
9. Share only the test output. Never share .env.local or API key values.

This patch is read-only: it does not sign or submit transactions. The patch does not include or alter .env.local.
